# Next.js app patterns (Next 16 / React 19 / Tailwind 4)

These patterns are already verified against this repo's lint, typecheck and build. Copy them instead of researching Next.js docs or `node_modules`.

## Fonts

Use `next/font/google` with the `variable` option, put the variable class on `<html>`, and map it in `@theme inline` in `app/globals.css`, exactly like Geist in `app/layout.tsx`. The import name is the font name with `_` instead of spaces (`Baloo_2`, `Nunito`, `Geist_Mono`).

```tsx
// app/layout.tsx
import { Nunito } from "next/font/google";
const nunito = Nunito({ variable: "--font-nunito", subsets: ["latin"] });
// <html className={`${nunito.variable} ...`}>
```

```css
/* app/globals.css */
@theme inline {
  --font-sans: var(--font-nunito);
}
```

## Page and layout types

`LayoutProps<"/">` and `PageProps<"/">` are global. They are generated by `next typegen`, which is part of `npm run typecheck`, so don't import them or look for them. Pass the route as the type argument (`PageProps<"/quiz/[id]">`); `params` and `searchParams` are Promises and must be awaited.

## Tailwind 4

There is no `tailwind.config`. Colors and fonts go into `@theme` / `@theme inline` in `app/globals.css` (e.g. `--color-brand: #7c3aed;` gives `bg-brand`, `text-brand`).

Lint fails on a class Tailwind doesn't know (`better-tailwindcss/no-unknown-classes`) — Tailwind itself would silently drop it:

- A value off Tailwind's scale goes in brackets: `rounded-[24px]`, `min-h-[92px]`, `text-[46px]`. Number suffixes are the spacing scale (×4px) and exist only for spacing-like utilities (`p-6`, `gap-6`, `h-20`), not for `rounded-*`, `text-*` or `min-h-100dvh`. Full viewport height is `min-h-dvh` / `min-h-screen`.
- The app's own CSS classes (e.g. an animation) go inside `@layer components { ... }` in `app/globals.css`; lint knows them from there.

## Client components

Put `"use client"` only in the component that holds state or handlers. `app/page.tsx` stays a server component and renders it.

## react-hooks lint rules (eslint-plugin-react-hooks v7)

The ones that most often fail lint in UI code:

- `react-hooks/set-state-in-effect`: no synchronous `setState` in a `useEffect` body. Calling `setState` inside a `setTimeout` callback or an event listener registered in the effect is fine. Derive values during render instead of syncing them with an effect.
- `react-hooks/purity`: no `Math.random()` or `Date.now()` during render. Do the work in an event handler (e.g. shuffle answers in the "start quiz" handler) and keep the result in state.
- `react-hooks/refs`: no reading `ref.current` during render; read it in handlers or effects.

## State in localStorage

Only through `usePersistedState` from `lib/persisted-state.ts`:

```tsx
"use client";
import { usePersistedState } from "@/lib/persisted-state";

const NO_SCORES: number[] = [];

export function Scores() {
  const [scores, setScores] = usePersistedState("scores", NO_SCORES);
  return <button onClick={() => setScores([...scores, 1])}>{scores.length}</button>;
}
```

- The fallback must be a module-level constant (not an inline `[]` or `{}`).
- The server render and first paint show the fallback; the saved value appears after hydration.
- `setValue` takes a value, not an updater function.

Don't load localStorage with `useEffect` + `setState` (fails `set-state-in-effect`), and don't read it in a `useState` initializer (hydration mismatch).

## Tests

Put testable UI logic (scoring, state transitions, data shaping) in pure functions in `lib/*.ts` with `lib/*.test.ts` next to them. Vitest runs in the `node` environment and only picks up `*.test.ts`, so don't write component tests.
